# ScopeWeaver as a hunter engine (optional, reviewed 2026-10-08)

[ScopeWeaver](https://github.com/cskwork/scopeweaver) is an AGPL derivative of ARTEX: an LLM
multi-agent autonomous pentest system (Go backend, Next.js UI, mitm traffic proxy, Playwright MCP,
skills, human approval queue). It can play the **hunter** role of this harness — it proposes and
records findings with bound traffic evidence — but it never replaces the disprover, the re-verifier
or Gate 6. Its findings enter `findings/` only through `scripts/record-verdict.py` after a fresh
context disprover run.

## Why it needs a wrapper
`guard/guard.go` states the rules-of-engagement scope mechanism "was removed". ScopeWeaver has no
allowlist of its own; its agents will follow redirects and bundle hostnames anywhere. Two controls
close that:
1. **Scope proxy.** `/home/user/tools/scopeguard-proxy.py` is a forward proxy that checks every
   CONNECT / absolute-URI request with `scripts/scope-enforce.py` against `scope/allowlist.txt`,
   chains allowed connections to the environment's upstream proxy, and logs allow/deny to
   `/home/user/tools/scopeguard-proxy.log`. Set it as ScopeWeaver's **global egress proxy**
   (`/api/settings` → `global_proxy`) *and* export `HTTP_PROXY`/`HTTPS_PROXY` to it in the process
   environment, so Go clients, curl and Playwright all go through it.
2. **Intercept rules.** Tools that bypass proxies (nmap, masscan, dnsx, raw sockets, ping, nc)
   are denied with global intercept rules (action `deny`, regex on the shell tool input). Anything
   not matched by an allow rule falls through to the LLM judge with `ask` on uncertainty.
Residual gap: a shell command that opens raw sockets to an IP without a hostname. Keep the
intercept deny list current, and review the audit log after every task.

## Setup (local build; Docker is not available in this container)
```bash
cd /home/user/tools/scopeweaver
# config.json: PostgreSQL 127.0.0.1:5432 user artex db artex (created by the orchestrator)
(cd web && npm ci && npm run build:static) && rm -rf server/webui/dist && cp -R web/out/. server/webui/dist/
CGO_ENABLED=0 go build -tags embedui -trimpath -o scopeweaver ./cmd/artex
HTTP_PROXY=http://127.0.0.1:8899 HTTPS_PROXY=http://127.0.0.1:8899 NO_PROXY=127.0.0.1,localhost \
  setsid nohup ./start.sh -addr 127.0.0.1:8787 -proxy 127.0.0.1:8788 > scopeweaver.log 2>&1 &
# first run: POST /api/auth/init {"password": ...} → JWT; UI at http://127.0.0.1:8787
```
An LLM key is required for exploration (`ANTHROPIC_API_KEY` / `OPENAI_API_KEY`, or the UI's LLM page).
The container has none; the human supplies it in the UI. Never paste keys into this repo.

## Driving it from Claude Code
`adapters/agent` is a stdio MCP server exposing read tools plus `scopeweaver_create_task` /
`scopeweaver_control_task` when `SCOPEWEAVER_ALLOW_WRITES=true`. It only talks to the local
backend, so mark it `@mcp-local scopeweaver` in `scope/allowlist.txt`; the target traffic is
generated by the backend behind the scope proxy, not by the MCP tool.

## Workflow in this harness
1. Gate 0 as usual: `scope/<program>.md`, `scope/allowlist.txt`, hook verified.
2. Create a ScopeWeaver task whose description is ONE slice from `recon/hypotheses.md`, with the
   allowlisted hosts named explicitly and the program's prohibitions in the goal text.
3. Let it run; review the approval queue; export findings + bound traffic.
4. Treat every finding as a hunter candidate: write it to `recon/candidates/<id>.md`, run the
   disprover and re-verifier, then `scripts/record-verdict.py`.
